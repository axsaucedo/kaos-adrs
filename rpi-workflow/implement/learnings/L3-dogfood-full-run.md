# L3 — Full dogfood run: chain and resume both hold; friction was wording-level only

The P2 dogfood (2026-08-30) ran the five skills end to end on a toy `linkcheck` CLI project across two deliberately separated fresh sessions: session A ran new-project → rpi-research → rpi-adrs under a fixed proxy-reviewer policy and stopped; session B started with zero context, determined the position in about two minutes purely from git log plus the files under `adr/001-linkcheck-cli/`, and took the effort through rpi-plan → rpi-implement to a merged `--no-ff` PR with real verification (manual scripts in the gitignored `tmp/`, then a smoke script asserting both the dead-link failure exit and the clean-pass exit).

What held without intervention: every gate committed alone with `Status:` transitions; the decision walk produced an examples-first ADR precise enough that the implementation matched its example output on first run and the plan had no unresolved forks; the cheatsheet needed no update because verified usage already matched it; resume-from-files needed no guessing.

Friction found (fixed on the stacked polish branch): new-project named the initial-request file only in its tree diagram, not in the step prose; rpi-research presented parallel fan-out as the default with the proportionate single-investigation case as an afterthought, which read as disproportionate for a tiny project. A third observation, not a defect: the skills give no wording for a decision-walk transcript when the reviewer is a fixed policy rather than a live user — irrelevant in real use, worth remembering for future automated harness runs.
