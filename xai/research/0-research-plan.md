# xai revitalization — research plan (stage 0)

This document is the index and plan for the research phase of the `xai` revitalization. It defines the components under investigation, catalogues the research already carried out (migrated in as numbered stages), enumerates the research still needed, and lists the validation spikes that de-risk the load-bearing assumptions before any design is committed. It is the entry point for everything under `xai/` and is read first.

## What this project is

`xai` (`github.com/EthicalML/xai`, source at `/Users/asaucedo/Programming/ethical/xai`) is a 2017-era tabular ML explainability and fairness toolkit — a ~1,150-line pandas/matplotlib library (`imbalance_plot`, `metrics_plot` sliced by `cross_cols`, permutation `feature_importance`, `balanced_train_test_split`), currently v0.3.0, published under The Institute for Ethical AI & ML. The revitalization pivots it from "explainability for tabular models when SHAP was new" to **explainability for 2026 agentic systems**: a small, provider-neutral analysis layer that turns agent trajectories — and, where the model is self-hosted, its internal state — into decision evidence.

The working thesis, refined across the research so far, is a three-layer arc that shares one foundation and sequences naturally:

- **A — Trajectory Diagnostics & Evidence Layer** (the wedge): a canonical trajectory schema plus adapters (OTel GenAI / OpenInference / Langfuse / Phoenix / plain JSON) and deterministic diagnostics and sliced metrics. "The pandas-of-agent-traces." Answers *what happened*.
- **B — Agent Decision Attribution** (the differentiator): context ablation and counterfactual replay with uncertainty, Monte-Carlo Shapley credit across steps/agents/tools, a planted-cause benchmark so explanations are falsifiable. Answers *why*, defensibly — the question no observability vendor answers.
- **F — Parametric Instrumentation** (the internals layer): when the agent runs on a self-hosted open-weights model, instrument the **inference server** (not the agent — the model virtually never runs in-process with the agent) to emit internal-state signals (logit-uncertainty, linear-probe readings, attention/attribution) as trace-correlated OTel spans that A's diagnostics and B's replay consume. Answers *why* with corroborating internal evidence, and is structurally unavailable to both observability vendors (they instrument the agent SDK, never the serving process) and interpretability labs (they work in-process on single models, never trajectories).

Positioning line: **"xai turned dataframes into fairness evidence in 2017; it turns agent trajectories into decision evidence in 2026."**

## Phase order and conventions

This docs area follows the same structure and order as the `memory/` effort in this repository: `research/` → `adrs/` → `plan/` → `impl/` (with `impl/learnings/` and `impl/progress/`) → `blog/`. The current phase is **research only**; documents here describe, compare, recommend, and validate — they do not change `xai` source. The `xai` repository is read-only for this effort; the only writes are to this `kaos-ai-docs` repository, plus throwaway spike code under the source repo's gitignored `tmp/`.

- **Numbering.** Research documents use a plain numeric stage prefix, `<n>-<name>.md`, starting at this plan (`0-research-plan.md`). Stages `1`–`8` migrate and formalize research already carried out; stages `9`+ are research not yet done. Spikes use an `S<n>` label and record their findings under `impl/learnings/`.
- **Cross-references.** Reference another research document as a Markdown link with `./` for same-folder links (e.g. `[stage 1](./1-landscape-observability.md)`). Reference `xai` source as repository-relative paths where a claim needs to be verifiable.
- **Markdown style.** No hard line-wraps inside paragraphs or list items — one continuous line each, soft-wrapped by the editor. Blank lines between paragraphs, lists, headings, tables, and code fences. Do not reference plan-step numbers inside document bodies; describe work by what it is.
- **Spikes.** Runnable validation code lives under the source repo's `./tmp/` (gitignored), in a throwaway venv; only the learnings writeup is committed here. Suppress noise to `./tmp/null`, never `/tmp`.
- **Commits.** One document per commit, `docs(xai): …` conventional form, describing exactly what was added. No session-URL trailer.

## Research components

The research is organized around seven components of the target system. Every research document and spike maps to one or more of these.

| Component | Core question | Primary stages |
|---|---|---|
| **C1 — Trajectory schema & ingestion** | What is the canonical normalized trajectory, and can it be populated from every major trace source? | 1, 9 |

The `instrument_<server>` (produce signals, hard) vs `instrument_<otel-backend>` (route signals, thin OTLP adapters for logfire/langfuse) distinction.

Spikes are small runnable harnesses that prove a load-bearing assumption before design commits. Each lives under the source repo's gitignored `./tmp/`; findings are written to `xai/impl/learnings/`. > **Campaign results (2026-08-01) — S3, S4, S5 executed; the F ADR is unblocked and stronger than the research predicted.** Learnings: [S3](../impl/learnings/S3-parametric-span.md), [S4](../impl/learnings/S4-llamacpp-internal-signal.md), [S5](../impl/learnings/S5-ebpf-semantic-recovery.md). Headlines fed to the ADR phase:
>
> - **Monitor-mode uncertainty is free and shippable now.** Exact full-vocabulary entropy + margin on vLLM's serve path via the documented `--logits-processors` flag — **zero patched lines** — matching HF fp32 to ~1e-5; same signals on llama.cpp via public API. Numerically demonstrated that truncated top-k logprobs *cannot* reconstruct entropy (>1 nat error), so this must be produced server-side, not from the API. This is stage 11's probe-free channel, validated.
> - **The residual (L2) probe tier is proven, with a known cost per engine.** llama.cpp: fully clean via the public `cb_eval` callback — named residual (`l_out-14`), exactly-once accounting, **byte-identical non-perturbation proof**, exact 4-way batch attribution, Metal within tolerance, cross-engine agreement with HF (probe delta <0.016). vLLM: the general-plugin contract **cannot** reach the model or batch map (research confirmed by runtime evidence), so it needs an **88-line installed-package patch** — which then achieved *exact* concurrency invariance (0.0 delta, concurrent vs sequential). A lifecycle race in the abort path was found and fixed with an ordering contract. Local stage-12 acceptance matrix: **11/12 pass**, the 12th (TP/PP rank cardinality) GPU-deferred.
> - **The full evidence pipeline works end to end on two engines.** Agent `traceparent` → server span → canonical `xai.parametric.observe` INTERNAL child, asserted programmatically, with bounded scalars, affirmative negative controls, and zero content/tensor leakage. One OTLP emitter + thin config verified against raw-collector / Logfire / Langfuse ingestion shapes.
> - **Zero-touch eBPF semantic recovery is real and maintainable — the reverse-engineering hypothesis held.** External uprobes recovered exact residual activations (24,576/24,576 floats bit-for-bit) and probe scalars from *outside* the inference process, with a 100% graph census. The brittleness protocol: llama.cpp version bump and Qwen→Llama architecture swap were both absorbed by **map regeneration with zero tool-code changes**; quantization (F16→Q8_0) was **works-unchanged**. Onboarding a new architecture is a sub-minute automated gate plus ~3 human steps. Verdict: a **constrained, opt-in capability** for pinned self-hosted CPU llama.cpp where patching the server is undesirable — a complement to the cooperative S4 path (96-line `llama-server` plugin), not a replacement. Hard constraint discovered: needs a real Linux kernel — **Docker Desktop's LinuxKit cannot attach uprobes; colima can**.
> **GPU tier executed (2026-08-01, one NVIDIA L4 on a disposable EC2 g6.xlarge; instance terminated after the campaign).** The deferred CUDA questions are now answered and folded into the S3/S5 learnings:
>
> - **SGLang is the first supported-path residual engine.** v0.5.16's official `--forward-hooks` passed the full 18/18 residual oracle (max delta 0.030 vs HF fp32), packed-prefill row selection, and attribution through a real continuous-batching row shift — via a 68-line mounted module, zero engine patches, token-non-perturbing. vLLM v0.26.0 V2 GPU re-proved zero-patch logits (with `vllm_xargs` request identity) and the residual concept as a version-sensitive **41-line** runner patch (the 88-line CPU patch did not port verbatim — private surfaces churn).
> - **Python hooks and production CUDA graphs are structurally incompatible on both engines**, by different mechanisms (SGLang registers after capture; vLLM's compiled/graph paths suppress the side effect). Exact residual observation is an opt-in **eager diagnostic**: measured cost **-65.8% (SGLang) / -66.9% (vLLM)** decode throughput vs production defaults, of which the hook itself is only -10.3%/-8.5% — the graph-disable dominates. **Zero-patch logits observation keeps graphs on at -23.0%** and is the always-on channel. A graph-aware engine observation interface is therefore a performance requirement to take upstream, not an API nicety.
> - **The eBPF GPU ceiling is precisely mapped.** CUPTI env-var injection into unmodified llama.cpp gives a zero-touch request-correlated GPU kernel-cost channel (~5% directional overhead; uretprobe time under CUDA measures submission, not execution). T2 graph structure stays host-readable under CUDA (backend-split, maps non-portable from CPU). T3 exact device values are **not reachable zero-touch** — CUDA UVA `/proc` reads return misleading zeros, no host staging exists, IPC needs owner cooperation — so exact GPU values route to the cooperative S4 `cb_eval` path. bpftime/PTX and concurrent/multi-GPU attribution remain explicitly untested.
> - **Remaining single-dependency deferral: TP/PP rank cardinality (stage-12 assertion #10)** — needs a multi-GPU box (short g6.12xlarge session); everything else in the matrix is closed or precisely scoped.
