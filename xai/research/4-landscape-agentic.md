## Agent failure analysis

- **MAST / "Why Do Multi-Agent LLM Systems Fail?" (NeurIPS 2025)** — Empirically derives 14 failure modes across specification/system design, inter-agent misalignment, and verification/termination; releases traces and an LLM annotator, but is a taxonomy/classifier rather than a general debugger. **Research-only.** [Paper](https://arxiv.org/abs/2503.13657) · [Artifact](https://github.com/multi-agent-systems-failure-taxonomy/MAST)
- **τ-bench (ICLR 2025)** — Shows tool-using customer-service agents are both weak and inconsistent, introducing `pass^k` to expose reliability across repeated trials rather than hiding it behind mean success. **Research-only.** [Paper](https://proceedings.iclr.cc/paper_files/paper/2025/hash/1b126cc38b8638e07bef37e7b2bb72bf-Abstract-Conference.html)
- **τ²-bench (2025)** — Adds dual-control environments where both user and agent change world state, and uses ablations to separate reasoning failures from communication/coordination failures. **Research-only.** [Paper](https://arxiv.org/abs/2506.07982)
- **Who&When (ICML 2025 Spotlight)** — Formalizes failure attribution to the responsible agent and decisive step using logs from 127 multi-agent systems; results show even strong LLM judges struggle with fine-grained attribution. **Research-only.** [Paper](https://proceedings.mlr.press/v267/zhang25cq.html) · [Code/data](https://github.com/ag2ai/Agents_Failure_Attribution)
- **AgentDiagnose (EMNLP 2025 demo)** — Runnable toolkit scoring trajectories on exploration/backtracking, decomposition, observation reading, self-verification, and objective quality, with web-domain visualizations; useful for inspection, not validated as production RCA. **Prototype.** [Paper/tool](https://aclanthology.org/2025.emnlp-demos.15/)
- **AgentDebug / AgentErrorBench (2025)** — Taxonomizes cascading root causes across memory, reflection, planning, action, and system modules, then localizes errors and feeds corrective feedback back to agents. **Research-only.** [Paper](https://arxiv.org/abs/2509.25370) · [Repository](https://github.com/ulab-uiuc/AgentDebug)
- **AgentRx (Microsoft Research, 2026)** — Synthesizes constraints from policies/tool schemas, validates every trajectory step, and returns an auditable violation log plus predicted critical step/category across τ-bench, incident response, and open-ended tasks. **Prototype.** [Paper](https://arxiv.org/abs/2602.02475) · [Code](https://github.com/microsoft/AgentRx)

## Behavioral evaluation and red-teaming

- **Anthropic agentic-misalignment simulations (2025)** — Sandboxed corporate scenarios elicited blackmail, espionage, and other insider-threat behavior across multiple vendors when goal completion conflicted with oversight; valuable stress tests, not prevalence estimates. **Research-only.** [Study and code](https://www.anthropic.com/research/agentic-misalignment)
- **Petri 2.0 (2025–2026)** — MIT-licensed auditor–target–judge system that autonomously builds multi-turn, tool-simulated scenarios and scores concerning behavior; unusually usable OSS, but judge dependence and evaluation awareness keep it pre-production. **Prototype.** [Repository](https://github.com/safety-research/petri) · [2.0 report](https://alignment.anthropic.com/2026/petri-v2/)
- **Bloom (2025)** — Generates reproducible scenario suites for a researcher-specified behavior and estimates frequency/severity, complementing Petri's open-ended discovery with targeted behavioral measurement. **Prototype.** [Report](https://alignment.anthropic.com/2025/bloom-auto-evals/) · [Repository](https://github.com/safety-research/bloom)
- **Inspect AI** — Maintained OSS evaluation substrate with isolated sandboxes, tool/MCP support, agents, multi-agent tasks, scoring, and logs; production-grade eval infrastructure, though diagnosis logic must be supplied by the practitioner. **Production-ready.** [Documentation](https://inspect.aisi.org.uk/)
- **AgentHarm (ICLR 2025)** — Public benchmark of explicitly malicious agent tasks designed to measure harmful task completion and refusal robustness under tool use. **Research-only.** [Paper](https://proceedings.iclr.cc/paper_files/paper/2025/hash/c493d23af93118975cdbc32cbe7323f5-Abstract-Conference.html) · [Dataset](https://huggingface.co/datasets/ai-safety-institute/AgentHarm)
- **SHADE-Arena (2025)** — Sandboxed long-horizon tasks for measuring agent sabotage and monitor detection, aimed at control evaluations rather than ordinary application QA. **Research-only.** [Study](https://www.anthropic.com/research/shade-arena-sabotage-monitoring)
- **WASP (2025)** — Tests web agents against realistic indirect prompt injections and finds advanced computer-use agents remain vulnerable to low-effort attacks. **Research-only.** [Paper](https://arxiv.org/abs/2504.18575)
- **Snyk Agent Scan** — OSS CLI inventories agents, skills, and MCP servers and scans descriptions/configuration/content for injection, secrets, malware, and sensitive-data risks; useful today but officially experimental and may execute configured MCP servers during discovery. **Prototype.** [Repository](https://github.com/snyk/agent-scan) · [Issue taxonomy](https://github.com/snyk/agent-scan/blob/main/docs/issue-codes.md)
- **AgentDoG 1.5 (2026)** — Trajectory-level diagnostic evaluator plus training-free online guardrail that labels safety/security failures; broader empirical validation and operational hardening are still limited. **Prototype.** [Paper](https://arxiv.org/abs/2605.29801) · [Code](https://github.com/AI45Lab/AgentDoG)

## Multi-agent and protocol-ecosystem analysis

- **MultiAgentBench (ACL 2025)** — Evaluates collaboration and competition across diverse tasks and coordination topologies, surfacing communication, planning, and role-allocation effects; it is benchmark infrastructure, not a live-system analyzer. **Research-only.** [Paper](https://aclanthology.org/2025.acl-long.421/)
- **LLM-Coordination (NAACL Findings 2025)** — Uses pure-coordination games and embodied Overcooked settings to isolate coordination ability from general task competence. **Research-only.** [Paper](https://aclanthology.org/2025.findings-naacl.448/)
- **Swarm-intelligence benchmark (2025)** — Provides environments and group-level metrics for emergent coordination under limited perception and communication. **Research-only.** [Paper](https://arxiv.org/abs/2505.04364)
- **AgenTracer / TracerTraj (2025)** — Uses programmed fault injection and counterfactual replay to generate supervision for identifying which agent and step induced a failure. **Research-only.** [Paper](https://arxiv.org/abs/2509.03312)
- **A2A protocol** — Production-oriented interoperability standard for opaque remote agents, but its deliberate preservation of internal opacity means it standardizes transport and identity—not causal auditability, shared provenance, or coordination diagnosis. **Production-ready protocol; analysis capability absent.** [Specification](https://a2aproject.github.io/A2A/latest/specification/) · [Project](https://github.com/a2aproject/A2A)
- **MCP Safety Audit / MCPScanner (2025)** — Multi-agent scanner generates adversarial tool/resource inputs, searches for vulnerability patterns/remediations, and emits MCP-server security reports; evaluated as a research artifact. **Prototype.** [Paper](https://arxiv.org/abs/2504.03767)
- **Cisco MCP Scanner** — Packaged OSS combines YARA, LLM-based behavioral analysis, source/dependency checks, and prompt-injection testing for MCP servers; practical pre-connect scanning, not cross-server or runtime trajectory analysis. **Prototype.** [Repository](https://github.com/cisco-ai-defense/mcp-scanner)
- **CSA `mcpserver-audit`** — Community OSS for vetting MCP servers and publishing findings to shared audit/vulnerability databases; useful ecosystem hygiene, but early and primarily static/pre-use. **Prototype.** [Repository](https://github.com/ModelContextProtocol-Security/mcpserver-audit)

## Decision and context attribution

- **Who&When (2025)** — Establishes agent-and-step blame as a benchmarked task but remains observational: an LLM judge reads the trace and predicts responsibility rather than testing causes. **Research-only.** [Paper](https://proceedings.mlr.press/v267/zhang25cq.html)
- **AgenTracer (2025)** — Counterfactual replay plus injected faults improves learned attribution beyond generic frontier-model judges, but its synthetic intervention pipeline is not yet a framework for arbitrary deployed agents. **Research-only.** [Paper](https://arxiv.org/abs/2509.03312)
- **AgentRx (2026)** — Its evidence-linked constraint violations make step attribution inspectable and policy-grounded, but still infer causality from a completed trace rather than rerunning controlled interventions. **Prototype.** [Paper](https://arxiv.org/abs/2602.02475)
- **Causal Agent Replay (2026)** — Models a run as a structural causal model, resamples individual steps, executes forward repeatedly, and reports per-step causal effects and Monte-Carlo Shapley credit with confidence intervals; closest direct match to causal trajectory attribution, but validated mainly on synthetic planted causes. **Prototype.** [Paper](https://arxiv.org/abs/2606.08275)
- **Context Attribution with Multi-Armed Bandits (ACL Findings 2026)** — Efficiently estimates which retrieved passages influence an answer, an adjacent method that could support agent context ablation but currently targets RAG outputs rather than sequential decisions. **Research-only.** [Paper](https://aclanthology.org/2026.findings-acl.565/)

**Bottom line:** no established OSS tool takes a real agent trace and attributes an outcome jointly across system/user prompts, individual messages, memory records, retrieved documents, tool observations, and inter-agent messages using controlled replay. Current work either labels a responsible step, checks policy constraints, or performs expensive experimental reruns over a narrower unit.

## Memory, belief, planning, and goal introspection

- **Evaluating Goal Drift in Language Model Agents (AIES 2025)** — Operationalizes long-horizon goal adherence and shows all evaluated agents drift to some degree, with scaffold design materially affecting persistence. **Research-only.** [Paper](https://ojs.aaai.org/index.php/AIES/article/view/36541)
- **MemBench (2025)** — Broad benchmark for agent-memory effectiveness across memory construction, retrieval, and utilization, useful for component selection but not for explaining a particular deployed decision. **Research-only.** [Paper](https://arxiv.org/abs/2506.21605)
- **MemoryAgentBench (2025)** — Tests accurate retrieval, test-time learning, long-range understanding, and selective forgetting through incremental multi-turn interaction. **Research-only.** [Paper](https://arxiv.org/abs/2507.05257)
- **Evo-Memory (2025)** — Streaming benchmark for whether self-evolving memories improve across experience without corrupting prior knowledge; closer to lifecycle behavior than static recall tests. **Research-only.** [Paper](https://arxiv.org/abs/2511.20857)
- **ABBEL (2025)** — Forces agents to expose an explicit natural-language posterior belief state before each action, creating an inspectable information bottleneck; this changes the agent architecture rather than recovering latent beliefs post hoc. **Research-only.** [Paper](https://arxiv.org/abs/2512.20111)
- **AgentDebug (2025)** — Explicitly labels memory, reflection, and planning failures in trajectories and localizes their earliest root cause, but does not reconstruct what facts the agent possessed or relied on at decision time. **Research-only.** [Paper](https://arxiv.org/abs/2509.25370)

**Bottom line:** memory benchmarks measure recall/use and goal-drift work measures behavioral deviation, but practitioner OSS does not yet reconstruct a time-indexed "epistemic state" (available, retrieved, believed, uncertain, contradicted), diff intended versus executed plans, or distinguish forgetting from ignored evidence and poisoned/stale memory.

## White space for practitioner-friendly OSS

The strongest revitalization opportunity is **an analysis layer above traces**, not another tracing SDK. A compact OSS direction would normalize trajectories from common agent frameworks/protocols and provide:

1. **Evidence ledger at decision time** — Version every prompt segment, message, memory item, retrieval, tool result, agent handoff, policy, and world-state observation; show what was available, selected into context, cited in reasoning, and contradicted.
2. **Causal context ablation/replay** — Remove, replace, or correct one context element and replay from the earliest affected decision under fixed environment snapshots; estimate outcome deltas, interactions, uncertainty, and cost instead of offering only LLM-judge blame.
3. **Plan/goal drift diagnostics** — Extract a lightweight goal/constraints/plan state at checkpoints, diff it over time, and flag dropped constraints, unexplained replanning, loops, premature termination, and progress stagnation using deterministic checks where possible.
4. **Multi-agent responsibility graph** — Convert flat events into provenance edges across delegation, claims, decisions, and tool effects; attribute downstream failures to originating information and handoffs, including shared or interacting causes rather than forcing single-agent blame.
5. **Failure-taxonomy adapters** — Ship executable MAST/AgentError-style classifiers with calibrated confidence, evidence spans, human correction, and project-specific extensions; existing taxonomies and datasets are not packaged as a dependable triage workflow.
6. **Behavioral test generation plus regression** — Combine Petri/Bloom-style scenario generation with reproducible world snapshots, repeated-run reliability (`pass^k`), trajectory invariants, and before/after behavioral diffs suitable for CI.
7. **Protocol-aware runtime audit** — Correlate MCP tool provenance/permissions and A2A identity/delegation with actual cross-step data flow, detecting compound risks such as poisoned tool output later causing exfiltration; current scanners mostly assess components in isolation before use.
8. **Evaluation of the evaluator** — Maintain human-labeled calibration sets, judge-disagreement views, counterfactual sanity checks, and confidence intervals; 2025–2026 attribution results show fluent LLM explanations are not reliable causal evidence.

### Recommended wedge for `EthicalML/xai`

Start with a framework-neutral **trajectory dataframe + analyzers**: import OpenTelemetry/JSON traces; normalize actors, context artifacts, decisions, tools, state changes, goals, and outcomes; then implement evidence-ledger views, MAST-style failure labels, context ablations, and plan-drift metrics. This preserves the library's original tabular-analysis identity while targeting the clearest gap between observability logs and research-only agent diagnosis. Avoid owning sandbox execution, tracing ingestion, or a full agent runtime initially; integrate with Inspect/Petri and existing trace exporters instead.
